This guide shows how printed output decides between styled and plain text, how
to wire that decision into your own `--color` flag, and how to print without
panicking on closed pipes. For lowering the color *depth* instead of switching
colors off, see [Degrade colors](/guides/degrade-colors/).

## Default behavior

The print family — `print`, `println`, `eprint`, `eprintln` and `write_to` —
honors a global [`ColorChoice`](/reference/color-control/). The default,
`Auto`, checks the environment and stdout:

<Code lang="rust" code={`use pretty_console::{Span, Styled};

// Styled when colors are enabled, plain text otherwise.
Span::new("hello").red().println();`} />

The detection runs once, is cached, and never touches the environment again on
the hot printing path. String rendering (`to_string`, `render`, `Display`) is
unaffected — see [Deterministic rendering](/explanation/rendering-model/) for
why.

## The environment variables pretty-console honors

| Variable | Effect |
| --- | --- |
| `FORCE_COLOR` | `0` turns colors off; `1`/`2`/`3` force them on (Node.js convention); empty means unset |
| `CLICOLOR_FORCE` | Any non-`0` value forces colors on |
| `NO_COLOR` | Any non-empty value disables colors ([no-color.org](https://no-color.org/)) |
| `CLICOLOR` | `0` disables colors |
| `TERM` | `dumb` disables colors |
| `COLORTERM` | `truecolor`/`24bit` advertises truecolor capability (used by detection, not by the on/off switch) |

`FORCE_COLOR` wins over `CLICOLOR_FORCE`; forcing variables win over
disabling ones. The exact precedence lives in
[`Color control`](/reference/color-control/).

## Wire a --color flag

Set the global choice after parsing your CLI arguments. `Auto` restores
environment-driven behavior:

<Code lang="rust" code={`use pretty_console::{set_color_choice, ColorChoice, Span, Styled};

enum ColorFlag {
    Always,
    Never,
    Auto,
}

fn main() {
    let flag = parse_color_flag(); // your --color handling
    set_color_choice(match flag {
        ColorFlag::Always => ColorChoice::Always,
        ColorFlag::Never => ColorChoice::Never,
        ColorFlag::Auto => ColorChoice::Auto,
    });

    Span::new("styled or plain, decided above").cyan().println();
}`} />

`set_color_choice` invalidates the cached `Auto` decision, so the next print
re-evaluates if you switch back to `Auto`.

## Print to stderr

Diagnostics belong on stderr; the `e*` variants behave like their stdout
siblings and honor the same choice:

<Code lang="rust" code={`use pretty_console::{Span, Styled};

Span::error("Disk full").eprintln();`} />

## Handle broken pipes with try_*

The plain print methods panic when the underlying stream fails — for example
when stdout is a closed pipe (`myapp | head -n 1`). The `try_*` variants
return `io::Result<()>` instead:

<Code lang="rust" code={`use pretty_console::{Span, Styled};

if Span::new("streaming…").dim().try_println().is_err() {
    // downstream closed the pipe — exit quietly
}`} />

`write_to` does the same for any writer you hold:

<Code lang="rust" code={`use pretty_console::{Span, Styled};

fn main() -> std::io::Result<()> {
    let mut buffer: Vec<u8> = Vec::new();
    Span::new("logged").green().write_to(&mut buffer)?;
    Ok(())
}`} />
